1. LICENCE AND PERMITTED USE

This software is a local authoring tool for the workshop courses held
in a Pentaho Content Manager repository: it opens the lab guides in
that repository, edits them with a live preview drawn by the learner
application's own renderer, scaffolds new courses and labs through
that repository's scripts, and can publish a course to the
distribution repository that workshop machines synchronise from. It is
used in Pentaho training and pre-sales work, and is provided for use
on authorised machines and by authorised personnel only. You may
install and use it for that purpose. You may not sell, sublicense,
rent or otherwise commercially exploit the software, and you may not
remove or alter any proprietary notice it contains.


2. YOUR COURSES AND YOUR REPOSITORIES

This software WRITES to the repository you point it at. Saving a lab
rewrites its guide file and re-stamps the derived metrics in its
manifest; the structure tree renames, reorders and deletes; creating a
course or lab runs the Content Manager's own scaffolding scripts; and
deleting a course removes its folder from disk. Nothing is written
until you choose it in the application, and the repository is a git
checkout, so ordinary version control remains your safety net. Keep it
committed.

Publish goes further: it commits and pushes the course to a remote
distribution repository using the git credentials already configured
on your machine, and workshop machines then synchronise what you
pushed. Content you publish becomes visible to everyone with access to
that repository and to the machines that pull from it. Review what a
guide contains - screenshots, hostnames, sample data, credentials
pasted into a code block - before publishing it.

You are responsible for having the authority to modify each repository
you open, to push to each remote you publish to, and for the content
you produce.

4. AI ASSISTANCE - WHAT IS SENT, AND WHERE

This software DOES use AI, as an optional assistant to the author, and
you choose the provider in its settings. This section describes what
leaves your machine so you can make that choice deliberately.

  (a) The features. Drafting a lab, rewriting a selected passage,
      reviewing the open lab, the assistant chat, and creating a
      course from an imported document each send text to the
      configured provider. Editing, saving, the preview, the
      structure tree, Verify and Publish do not: they call no model
      at all.

  (b) What is sent. The lab text, passage, document or question you
      act on, together with the instruction the feature was built
      with. A review or a rewrite sends the guide you have open. An
      import sends the text extracted from the document you upload.

  (c) Where it goes. With the default provider, Ollama, generation
      runs on your own machine and nothing leaves it. If you select
      Anthropic or OpenAI, the text in (b) is sent to that company's
      service over the internet and is subject to their terms and
      their data handling, not this notice. Selecting a hosted
      provider for a guide that contains customer material, internal
      hostnames or unpublished product detail is a disclosure
      decision; make it knowingly.

  (d) Documentation grounding. When enabled, features may first send
      a short query derived from your text to the Pentaho
      documentation site's public endpoint to retrieve reference
      material. It is off by default.

  (e) Credentials. API keys are read from the ANTHROPIC_API_KEY and
      OPENAI_API_KEY environment variables at the moment of the call.
      The application never stores a key, and its settings file
      records only which provider and model you chose.

  (f) The output is a draft. Everything a model produces is inserted
      for you to read, edit and accept. Nothing generated is
      published, deployed or shown to a learner without an author
      putting it there. Model output can be confidently wrong,
      including about Pentaho itself - the review feature is built on
      that assumption, and lists findings it cannot locate in your
      guide separately for exactly that reason. Check technical
      claims before they reach a workshop.


5. DATA PROTECTION AND PRIVACY

  (a) Data kept on your machine. The application's own files are its
      settings (the provider, model and repository you chose) and a
      cache of the distribution repository used by Publish, both in
      your per-user application data folder. The courses themselves
      live in the repository you point it at, not inside the
      application.

  (b) Credentials are never persisted by this software. Model API
      keys come from the environment (section 4(e)). Git
      authentication is whatever your machine already has - a
      credential manager or similar - and is used, never stored or
      copied, by this software.

  (c) Personal data in course content. Course material can contain
      personal data: screenshots of real systems, sample datasets,
      named individuals in examples, and the contact details a guide
      asks a learner to use. Whatever you put in a guide is what gets
      committed, published and - if you use a hosted model on that
      guide - sent to that provider. Prefer synthetic examples.

  (d) Controller. The organisation operating the software determines
      the purposes and means of this processing and is the data
      controller. It is responsible for its own privacy notice,
      lawful basis, retention periods and transfer mechanisms. The
      authors of the software supply a tool and operate no service on
      your behalf.

  (e) Your rights. Subject to applicable law you have the right to
      request access to, rectification of, or erasure of your
      personal data, to restrict or object to its processing, and to
      data portability, and to complain to your data protection
      supervisory authority. Exercise these rights with the
      organisation named in its privacy notice. Locally held content
      can be removed at any time by deleting the files, though
      published history remains in the repositories you pushed to.

  (f) Data minimisation. Use the local provider where the content is
      sensitive, enable documentation grounding only when it helps,
      and publish only the courses you intend to distribute.
